# Phase 29 — ESP Audio Output — TTS DSP chain — SUMMARY

**Завершено:** 2026-06-01
**Ветка:** `ESP-Audio-Out`
**Статус:** аудио-часть готова; аппаратный хрип вынесен в deferred

## Цель

Вывод голоса Адама на ESP-спикеры (2× MAX98357A стерео) как штатный путь + программная DSP-обработка TTS для громкости и качества на маломощных динамиках (3 Вт, 200 Гц–20 кГц, 4 Ом, 3.3 В).

## Что вышло (коммиты)

| Commit | Что |
| ------ | --- |
| `2b27ac3` | Слайс 1: `output_target → esp32_speaker`, route TTS на ESP `/speaker`, комментарий PinsConfig MAX98357A x2 |
| `e99ced0` | DSP-цепочка (Stage A+B): новый `System/adam/audio_dsp.py` — HPF → компрессор → presence-EQ → makeup → брикуолл-лимитер; soxr вместо audioop.ratecv; параметры в `tuning.voice.dsp` (hot-reload) |
| `0b7361a` | Чистое воспроизведение: paced-подача на ESP, edge-fade, хвост-тишина; финальный профиль; makeup снижен 6→4 из-за аналогового хрипа |

**Финальный профиль (`tuning.voice.dsp`):** hpf 240, makeup +4, comp 2.0/−24 (knee 6, atk 10, rel 120), presence +2.5 дБ @ 3 кГц (Q 0.9), limiter −1 dBFS. Плюс `voice.speed_multiplier` 1.1 → 1.0.

## Решения

- **Брикуолл-лимитер заменил hard-clip** в `_apply_wav_volume` — гарантия пика ≤ −1 dBFS независимо от makeup/volume.
- **Компрессор = источник громкости.** Stage A (только пик-лимитер + makeup) почти не добавляет громкости на уже-горячем Silero (пик −2 dBFS): прирост съедается лимитером. Реальный +6.7 дБ RMS даёт компрессия (придавить пики → поднять всё).
- **Фикс-gain, без пофразной нормализации** (D-06) — сохраняет динамику, нет «накачки» между фразами.
- **Мягкий характер** (ratio 2.0) — выбор на слух; агрессивный профиль (hpf 300/comp 4) после чистого воспроизведения оказался не нужен.

## Уроки и сюрпризы (главное этой фазы)

- **Обрывы громкого звука = ПИТАНИЕ, а не код.** Полсессии обрывы списывались на `:81`/overflow. Реальная причина: ESP/усилители питались **от USB** (забыт основной БП) — громкий звук просаживал общий 3.3 В рельс MP1584 (W5500 Ethernet + INMP441 + 2× MAX98357A) → Ethernet ронял TCP → `Connection reset` посреди стрима. С БП 12 В/16 А все уровни (вкл. 100%) играют чисто. **Decisive-тест:** один и тот же WAV ×0.3 играет, ×1.0 рвёт. → [[project_esp_speaker_playback]].
- **`speaker_overflows` ≠ потеря звука сам по себе**, НО full-speed заливка (~1000 overflow/фразу) даёт реальные дропы → щелчки. Лечится **paced-подачей** (скорость воспроизведения, prime 20 КБ) → 0 overflow.
- **Наивный paced опасен:** при заминке Python-цикла накопленный «долг» выливается burst'ом в кольцо 32 КБ → порча указателей → **белый шум** (Δover+Δunder одновременно). Фикс: ровный клок со сбросом долга (худшее — тихий underrun, не каша).
- **Концевые щелчки** = стартовый транзиент фильтров + I2S-stop pop MAX98357A. Лечатся 12 мс fade-in/out + ~60 мс хвоста тишины.
- **Скорость 1.1 завышала тон** — голос «очень высокий». 1.0 = натурально.
- **Хрип — аналоговый, не DSP.** Присутствует даже на raw (DSP off), растёт с громкостью. Причина: GAIN-пин MAX98357A floating = **+15 дБ** перекачивает 3-ваттный динамик на 3.3 В. Софтом не лечится.

## Verification

- DSP-модуль: пик ≤ −1.00 dBFS даже при +12 дБ/vol 2.0 (лимитер держит); fail-safe на битом входе; soxr ratio корректен.
- Воспроизведение: 0 overflow / 0 underrun на серии из 10 фраз (paced burst-safe); подтверждено на слух — щелчки и белый шум ушли.
- Профиль подтверждён на слух пользователем.

## Deferred (следующие задачи)

- **Хрип (аппаратно):** понизить GAIN-пин усилителей +15 → +9/+6 дБ; и/или питание усилителей на **5 В** (реальный потолок громкости ~1.4 Вт на 3.3 В).
- **Firmware backpressure на `:81`:** чтобы ESP при заполнении кольца придерживал чтение сокета, а не дропал → можно слать full-speed без дропов и без хрупкости Python-paced.
- **48 кГц на firmware speaker** — чистый ×2 апсемпл из 24k.
- **Самоэхо в реальном диалоге** (п.1 из обзора): громкий вывод рядом с INMP441 — проверить REPLY-фазу через оркестратор, при необходимости поднять `post_tts_discard_window_ms`.
