# Phase 42 — UI Design Contract: WebUI Reorganization

> Visual and interaction contract for the operator WebUI structural refactor.
> Generated by gsd-ui-researcher. Verified by gsd-ui-checker.
>
> **Context:** This is a reorganization of an existing dark-theme operator SPA, not a greenfield design.
> The existing CSS token system in `System/WebUI/static/css/tokens.css` is the source of truth.
> This document specifies only **deltas** — new patterns not yet in the codebase — plus explicit
> confirmations of existing tokens used in new components.

---

## Design System

| Property | Value | Source |
|----------|-------|--------|
| Tool | none | No shadcn, no component library |
| Preset | not applicable | Vanilla JS SPA |
| Component library | none | Custom `el()` builder pattern |
| Icon library | Unicode symbols (▸ ▾ ✕ ✓) | Existing pattern in main.js |
| Font (sans) | Inter, system-ui, Segoe UI, -apple-system | `--font-sans` in tokens.css |
| Font (mono) | JetBrains Mono, SF Mono, Cascadia Code, Consolas | `--font-mono` in tokens.css |
| Markdown renderer | marked.js via CDN | **NEW — not yet in index.html** (confirmed by grep: no markdown lib loaded) |

**Registry safety:** No shadcn, no third-party component registries. One new CDN dependency: marked.js.
Marked.js is a well-audited open-source library (MIT, no telemetry, no network calls at runtime).
Safety gate: not required for CDN script (not a shadcn registry block).

## Spacing Scale

Existing system uses an 8-point scale in CSS. All new components MUST use only these values.

| Token | Value | CSS form | Confirmed usage |
|-------|-------|----------|-----------------|
| xs | 4px | `4px` | `.dot` size, inline icon gaps |
| sm | 8px | `8px` | `.card-header` gap, `.btn` padding-v, `.badge` padding |
| md | 16px | `16px` | `.card-body` padding, `.main` padding, `.nav` padding |
| md+ | 20px | `20px` | `.main` padding (top) |
| lg | 24px | `24px` | `.nav-link` indent for 3rd level (new), `.navLink(indent)` |
| xl | 28px | `28px` | 3rd-level nav link padding-left (new — see Nav section) |

**New exceptions for this phase:**
- 3rd-level nav indent: `padding-left: 28px` (14px base + 14px additional indent)
- Flora table cell padding: `8px 12px` (matches `.input` padding, consistent)
- Identity block textarea min-height: `120px` (content-driven exception, not layout spacing)
- Markdown rendered view body: `16px` all sides (matches `.card-body`)

No 44px touch target exceptions required — this is a desktop operator UI (1024px minimum).

## Typography

All existing font-size tokens are confirmed from `tokens.css`. New components use ONLY these sizes.

| Role | Token | Value | Weight | Line Height | Usage |
|------|-------|-------|--------|-------------|-------|
| Caption / label | `--fs-xs` | 11px | 500 | 1.4 | `.card-title`, `.badge`, `.nav-section`, speed sub-labels in flora table |
| Body / UI default | `--fs-s` | 13px | 400 | 1.5 | `.nav-link`, `.btn`, `.input`, `.kv` values, table cells |
| Content | `--fs-m` | 14px | 400 | 1.5 | Rendered markdown body, textarea content |
| Heading | `--fs-l` | 17px | 500 | 1.2 | Page section headings (if any) |

> **Note:** `--fs-xl` (22px) is an existing token in tokens.css but is not used in Phase 42.
> It is excluded from the table above (max 4 sizes per contract).

**New typography deltas for this phase:**

1. **Markdown rendered view** — body text at `--fs-m` (14px), weight 400, line-height 1.6.
   Headings in rendered MD: `--fs-l` (17px) weight 500. Code blocks: `--font-mono` at `--fs-s` (13px),
   background `var(--bg-2)`, padding `4px 8px`, border-radius `var(--radius-s)`.

2. **Flora table speed sub-label** — field name shown below the number input (e.g. `period_ms`).
   Size: `--fs-xs` (11px), color: `var(--dim)`, font: `--font-mono`. Placed as a `<div>` below the `<input>`.

3. **AIIM aspect labels** — two lines: aspect code (e.g. `se`) at `--fs-xs` mono + dim color;
   aspect name (e.g. «Самость») at `--fs-s` weight 500 text color. Same two-line pattern as `.card-title`.

4. **3rd-level nav items** — same font as 2nd-level (`.nav-link`): `--fs-s` (13px), weight 400.
   Visual differentiation through indentation only, not font change.

5. **Nav section dividers** — existing `.nav-section` class: `--fs-xs` uppercase letter-spacing 0.1em,
   color `var(--dim)`. Reuse as-is for top-level section labels in 3-level nav.

## Component Patterns

### 1. 3-Level Navigation (NAV_STRUCTURE extension)

**Structure in `NAV_STRUCTURE` array (new item types):**

```
{ type: 'link', key, label }                    — top-level direct link (Чат)
{ type: 'group', label, id, children: [...] }   — collapsible group (Настройки, Система, Диагностика)
  children may contain:
    { type: 'link', key, label }                — 2nd-level page link
    { type: 'subgroup', label, children: [...] } — collapsible sub-group (Агент within Настройки)
      children: { type: 'link', key, label }    — 3rd-level page link
{ type: 'separator' }                           — horizontal line divider
{ type: 'section-label', label }                — uppercase dim label (existing .nav-section)
```

**Visual specification — collapsed group header:**
- Element: `<button class="nav-link">` (existing style, full width)
- Arrow: `▸` at `color: var(--accent)`, width 14px, text-align center
- Group label: plain text at `--fs-s`, color `var(--muted)`
- No extra padding vs current — same `padding: 8px 14px` as `.nav-link`

**Visual specification — expanded group body:**
- Container: `display: flex; flex-direction: column` (existing pattern)
- 2nd-level links: `padding-left: 24px` (existing `indent=true` pattern)
- 2nd-level sub-group header: `<button class="nav-link nav-link-l2-group">` — same as group header but with `padding-left: 24px` and smaller arrow `▸`/`▾` in dim color (`var(--dim)`)
- 3rd-level links: `padding-left: 40px` (24px + 16px additional step)

**Active state:** `.nav-link.active` unchanged — left green border + bg tint + accent text.
Active state applies to the leaf (3rd-level) link only. Parent group and sub-group remain in default state when a child is active.

**Collapse persistence:** localStorage keys:
- Level 1 group: `navGroup_{id}` (existing)
- Level 2 subgroup: `navGroup_{parentId}_{sublabel}` (new, e.g. `navGroup_settings_Агент`)

**New CSS class needed:**
```css
/* Add to layout.css */
.nav-link-l2-group {
  /* same as .nav-link but with dimmer arrow */
}
/* No separate class needed — use inline padding on the button element */
```
Decision: use inline `style="padding-left:24px"` on subgroup headers and `style="padding-left:40px"` on 3rd-level links. No new CSS class needed — matches existing `navLink(key, label, indent)` approach.

**Complete nav hierarchy (from D-02):**
```
Чат                            ← direct link, key="chat"
Настройки (collapsible)
  Агент (sub-collapsible)
    Личность                   ← key="agent/persona"
    Инструкции                 ← key="agent/instructions"
    Память                     ← key="agent/memory"
Система (collapsible)
  Аудио и видео                ← key="system/audio"
  Сервисы и модели             ← key="system/services"
  Подсистема ESP32             ← key="system/esp32"
Технофлора                     ← direct link, key="flora"
Диагностика (collapsible)
  Метрики и логи               ← key="diagnostics/metrics"
  Система                      ← key="diagnostics/system"
  Подсистема                   ← key="diagnostics/esp32"
```

**Hash routes:** `#/agent/persona`, `#/system/audio`, etc. Router key = `agent/persona` (slash in key, valid JS object key).

### 2. Markdown Render+Edit Toggle (Инструкции page)

**Default state — Rendered view:**
- Container: `.card` with `.card-header` + `.card-body`
- Card title: file display name (e.g. "System.md", "Lore.md", "Abilities.md")
- Card header right slot: `<button class="btn">Редактировать</button>` — `.btn` (ghost style, NOT primary)
- Card body content: `div.md-render` — marked.js output injected as `innerHTML`
- `div.md-render` styling: font `--font-sans`, size `--fs-m`, line-height 1.6, color `var(--text)`
- Rendered `h1/h2/h3`: color `var(--text)`, weight 500
- Rendered `code`/`pre`: `background: var(--bg-2)`, `font-family: var(--font-mono)`, `font-size: var(--fs-s)`, padding `4px 8px`, border-radius `var(--radius-s)`
- Rendered `p` margin-bottom: `12px`
- Rendered `ul/ol`: `padding-left: 20px`, `margin-bottom: 8px`

**Edit state — Textarea view:**
- Same `.card` wrapper, `.card-header` changes: title + "Сохранить" `.btn-primary` + "Отмена" `.btn-ghost`
- "Редактировать" button disappears when in edit state
- Card body: `<textarea class="textarea field-wide">` — full width, `min-height: 240px`, monospace font
- Textarea pre-populated with raw markdown content
- No auto-save — explicit Save required

**Toggle logic:** single boolean `isEditing` per file card. On "Редактировать": save textarea value = current rendered source, show textarea, hide rendered div, swap buttons. On "Сохранить": PUT `/api/persona {path, content}` → on success show toast + return to rendered view. On "Отмена": discard textarea changes, return to rendered view.

**Loading state:** Card body shows `—` (dash) while file loads. No spinner needed (fast local fetch).

**Error state:** If PUT fails, show `.toast.bad` "Ошибка сохранения: {message}". Stay in edit state so user can retry.

**Marked.js integration in index.html:**
```html
<!-- Add before </head> or before main.js script tag -->
<script src="https://cdn.jsdelivr.net/npm/marked/marked.min.js"></script>
```
Usage in JS: `el("div", { html: marked.parse(rawMarkdown) })` or `div.innerHTML = marked.parse(content)`.
Configure: `marked.setOptions({ breaks: true, gfm: true })` once on startup.

## Interaction & Animation

### 3-Level Nav Collapse/Expand

- **Trigger:** Click on group or subgroup header button
- **Animation:** `display: none ↔ flex` toggle (no animation — matches existing pattern).
  Reason: existing `buildNav()` uses `display:none`/`flex` directly, no CSS transition on display.
  Do NOT add height animation — inconsistent with existing groups would be jarring.
- **Arrow rotation:** `▸` → `▾` (textContent swap, immediate, no animation)
- **State persistence:** localStorage on every toggle

### Markdown Render/Edit Toggle

- **Trigger:** Click "Редактировать" button
- **Animation:** Swap visibility of `div.md-render` and `textarea` with no animation (immediate).
  Reason: content swap, not overlay — animation would feel laggy on large markdown files.
- **Button label:** "Редактировать" (view mode) → header shows "Сохранить" + "Отмена" (edit mode)
- **Textarea focus:** Auto-focus textarea on entering edit mode: `ta.focus()`

### AIIM Slider Updates

- **Trigger:** `input` event on range slider (live, not `change`)
- **Live value display:** Update `<span>` next to slider on every `input` event
- **Save:** NOT auto-save. Explicit "Сохранить матрицу" button (`.btn-primary`) below the grid.
  Button label changes to "Сохраняется…" during PUT, returns to "Сохранить матрицу" on success.

### Flora Table "Показать сейчас"

- **Sequence:** (1) Collect row's current input values → (2) PATCH config → (3) on PATCH success, POST state trigger → (4) toast result
- **Button loading state:** `disabled + textContent = "…"` during sequence, restore `▶` on complete
- **Failure:** If PATCH fails, show `.toast.bad`, do NOT send state trigger

### Preset Selector (AIIM)

- **Trigger:** Click inactive preset badge → POST `/api/tuning/preset/{name}` → on success reload tuning data → redraw sliders + update active badge
- **Loading state:** All preset badges get `opacity: 0.5` during POST. Restore on complete.
- **No confirmation dialog** — preset apply is reversible (sliders can be manually adjusted and saved back)

### Save Operations (general)

- **Pattern:** All save buttons follow: loading state → API call → toast → restore button.
- **Toast duration:** 2500ms for success, 5000ms for error (matches existing pattern in main.js)
- **No confirmation dialogs** for config field saves (they are non-destructive, hot-reloadable)
- **No destructive actions in this phase** — dead page removal is code-only, not user-facing

### Tabs (Память page sub-tabs)

- **Trigger:** Click tab button → show/hide content `div`s (display none/block)
- **Animation:** none (immediate, matches nav pattern)
- **State persistence:** NOT persisted to localStorage (re-opens to "Базовая" on page reload)
