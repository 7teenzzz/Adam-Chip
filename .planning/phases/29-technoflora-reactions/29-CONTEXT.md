# Phase 29: Technoflora Reactions - Context

**Gathered:** 2026-06-04
**Status:** Ready for planning

<domain>
## Phase Boundary

Реактивный физический слой установки: **светофлора** (PCA9685 каналы 0–10, лампы
Эдисона) и **виброфлора** (каналы 11–14, моторы) откликаются на **6 состояний
голосового пайплайна** — покой → детекция обращения → слушание (ASR) → раздумье
(LLM) → ответ (TTS) → пробуждение.

Слой управляется **событиями оркестратора** (EventBus), а не выводом LLM —
детерминированно, без латентности, всегда корректно. Отдельно от `action.py`
(mood→scene от LLM остаётся как есть).

**В scope:** анимационный движок в прошивке ESP, event-слой на Jetson,
RMS-реактивная подсветка речи, Config-First параметризация, политика виброфлоры.

**Вне scope:** новые типы реакций сверх 6 состояний, изменение `action.py`,
проактивная моторика на сцену (это Phase 28 `scene_director` / `scene_delta`).
</domain>

<decisions>
## Implementation Decisions

### Раскладка и язык движений (из discuss-концепта)
- **D-01:** Светофлора — **кластер без пространственного порядка**. Направленные
  эффекты (волна / бегущий огонь / цветение 0→10) исключены. Вместо них —
  коллективные и случайно-групповые приёмы: коллективное дыхание, блуждающие
  вспышки (случайные подмножества каналов), случайное прорастание, коллективный
  «вдох» к голосу.
- **D-02:** Каналы: свет = **0–10** (11 шт), вибро = **11–14** (4 шт), канал 15
  свободен. Маски каналов — в Config.

### Архитектура
- **D-03:** **Гибрид с уточнением.** Фоновые состояния (покой / детекция /
  слушание / раздумье / пробуждение) — автономные анимации **в прошивке ESP** по
  `id + параметры`. Состояние **ответа (RMS, состояние 4) — Jetson-driven**:
  Jetson сам гонит кадры яркости в реальном времени (см. D-06).
- **D-04:** Технофлора — **реактивный слой по событиям пайплайна**, подписан на
  `EventBus` (`oww_detected` → детекция, `asr_start` → слушание, `llm_start` →
  раздумье, `tts_start` → ответ, `tts_end` → покой/слушание). Не пересекается с
  `action.py`.
- **D-05:** Новый эндпоинт прошивки `POST /api/flora/state {state, params}` для
  переключения автономных анимаций. Пресеты анимаций: `breathe` (покой),
  `accent` (детекция — одиночный импульс), `attentive` (слушание),
  `think_pulse` (раздумье — блуждающие вспышки), `wake_bloom` (пробуждение —
  случайное прорастание).

### Объём первой волны
- **D-06:** **Все 6 состояний сразу** в одной фазе, включая RMS-синхронизацию и
  кинематографичное пробуждение. Не разбиваем на волны.

### RMS-синхронизация речи (состояние 4)
- **D-07:** **Jetson стримит кадры в реальном времени.** Jetson считает
  RMS-огибающую из TTS WAV, проигрывает аудио (jetson_hdmi) и параллельно гонит
  кадры яркости каналов 0–10 по HTTP (`/api/pca9685/channels` батч) в такт
  плейбэку. Потолок ~15 fps (HTTP round-trip + лимит сокетов ESP) — приемлемо
  при тепловой инерции ламп. **Sync тривиален**: Jetson владеет и аудио, и
  светом — один таймер от старта плейбэка; латентность-офсет HDMI-буфера —
  параметр в Config.
- **D-08:** База яркости речи ~25%, пики ~90%, плюс редкие случайные «искры» на
  пиках для фактуры (кластер-friendly, без «центра»).

### Переходы и barge-in
- **D-09:** **Короткий crossfade ~150–250 мс** на переходах состояний (нет
  резких скачков; лампы и так инерционны). **Barge-in мгновенный**: если
  пользователь перебивает в состоянии ответа — свет сразу рвётся в слушание.
- **D-10:** НЕ переиспользуем тайминги `scene_director` (sustain/cooldown/
  hysteresis) — они для проактивной моторики, у технофлоры отзывчивость
  приоритетна.

### Характер виброфлоры
- **D-11:** **Тонкое присутствие, ритмически связана со светом.** Вибро — едва
  ощутимый пульс/присутствие, следует ритму света. **Молчит в состоянии
  слушания** (моторы рядом с INMP441 наводят вибрацию в микрофон → мешают ASR).
- **D-12:** Интенсивность/амплитуда вибро — параметр в Config (по умолчанию
  сдержанная).

### Config-First
- **D-13:** Все числа — в `System/Config.json` + `Config.schema.json`: диапазоны
  duty per state, периоды анимаций, gamma (~2.2, перцептивная коррекция),
  маски каналов (свет 0–10 / вибро 11–14), frame interval речи,
  латентность-офсет HDMI, crossfade ms, интенсивность вибро. Новая секция,
  напр. `flora`.

### Claude's Discretion
- Внутренняя параметризация прошивочного движка (сколько knob'ов наружу vs
  фиксированные пресеты) — решает researcher/planner.
- Точные кривые яркости, периоды, gamma-значения — стартовые дефолты на
  усмотрение planner, далее калибруются на железе.
- Формат payload `/api/flora/state` и схема RMS-кадров — на усмотрение planner.
</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- `MCUClient.set_channels(updates)` — атомарный батч-апдейт каналов; идеален для
  кадров RMS-стрима и crossfade (все 16 каналов одним POST).
- Firmware `writeAllChannelsRaw` / `applyPca9685Updates` — атомарная запись всех
  каналов за один I2C-burst; движок анимаций пишет кадры через это.
- `_get_wav_bytes_sync(text)` в `inference.py` — отдаёт сырой WAV без плейбэка →
  источник для расчёта RMS-огибающей.
- `EventBus` + существующие события пайплайна (`oww_detected`, `asr_*`, `tts_*`)
  — готовые триггеры состояний, новые эмиссии могут не понадобиться.

### Established Patterns
- **Config-First** — все числа в Config.json + schema; hot-reload через
  `Settings.load()`/`tuning.py`.
- **`_NO_PROXY_OPENER`** — любой HTTP к ESP только через него (v2ray leak'ит
  сокеты → исчерпание 4-слотового пула ESP:81). Новый flora-клиент обязан
  следовать.
- **Статические сцены в прошивке** (`kPca9685Scenes[]`) — динамика их не
  заменяет; движок анимаций — новый слой поверх raw-записи каналов.
- **PWM 1000 Гц, 12-bit** — лампы Эдисона инерционны → сглаживают PWM (хорошо
  для дыхания/свечения, плохо для резкого строба); gamma-коррекция нужна.

### Integration Points
- Jetson: новый модуль (напр. `System/adam/flora.py`) — подписка на EventBus →
  `MCUClient` flora-вызовы + RMS-стрим из TTS-пути.
- Прошивка: новый анимационный модуль + роут `/api/flora/state` в
  `WebServerModule.cpp`.
- TTS-плеер: точка старта плейбэка = точка старта RMS-кадров (один таймер).
</code_context>

<specifics>
## Specific Ideas

- Метафора всего слоя: **«живой организм»** — свет = свечение/дыхание/
  биолюминесценция, вибро = пульс/сердцебиение/тактильное присутствие.
- Концепции 6 состояний (детально проговорены в discuss): покой = медленное
  дыхание 6–8 с; детекция = быстрый вдох до ~75% + чёткий вибро-импульс;
  слушание = плато ~40% + коллективный вдох по RMS голоса (вибро молчит);
  раздумье = притухание ~20% + блуждающие вспышки 1.5–2 с + мягкий двойной
  вибро-пульс; ответ = яркость по RMS (25%↔90%) + искры; пробуждение =
  случайное прорастание из тьмы → общий вдох → оседание в дыхание.
- Текущий boot-сценарий прошивки `test_all` (71% всё включено) — чисто
  диагностический; `wake_bloom` его заменит для выставки.
</specifics>
