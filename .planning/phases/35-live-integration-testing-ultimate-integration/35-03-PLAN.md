<live_state_facts>
- Flora mechanism (carried Phase 30 D-03 coexistence): on tts_started the controller sends the ESP
  firmware into `external` (its own animation suppressed) and the RMS of Adam's speech
  (feed_speech_wav → _rms_envelope → _rms_stream → set_channels) drives the light channels; on
  tts_finished it settles to `breathe`. Between answers the firmware runs background animation.
  Light channels and vibro channels come from Config flora.light_channels / flora.vibro_channels.
  'attentive' (listening) forces vibro OFF (vibro couples into the INMP441 and corrupts ASR).
- Flora API: POST /api/flora/state {"state":"breathe"|"accent"|"attentive"|"think_pulse"|"wake_bloom"|"external"|...}
  pushes a preset immediately; GET /api/flora/config previews effective per-state params.
- IMPORTANT CAVEAT: BRANCH condition 4 (ESP reflash under the flora firmware: vibro 0-3 / light 4-14)
  is DEFERRED to AFTER a green push — it is NOT part of this phase. The ESP is currently flashed from
  070ab4b (no-flora firmware). Therefore flora behavior on hardware may be PARTIAL/degraded until
  reflash. Record what the current firmware actually does; a non-reflashed firmware NOT showing the
  final channel map is NOT a Wave-4 code defect — note it as "blocked on reflash (BRANCH cond 4)".
- Skills: jokes intent keywords [пошути, анекдот, рассмеши, шутк, смешн, развесели] → verbatim
  short-circuit, response has skill='joke', skill_id. Weather keywords [погод, на улице, за окном,
  холодно, тепло, жарко, дожд, снег, ветер, градус] → injects cached weather context (offline note
  if cache stale — failure≠silence invariant).
- Memory: each turn adds a 'viewer' + 'adam' row to dialogue_turns in memory.sqlite3. Episodes are
  JSONL under data/adam/memory/episodes/*.jsonl, salience-gated, written at session end.
- Skills/memory text turns can run in maintenance OR exhibition via /api/agent/turn — no mic needed.
- curl --noproxy '*' for localhost; ESP Python HTTP via _NO_PROXY_OPENER.
</live_state_facts>
