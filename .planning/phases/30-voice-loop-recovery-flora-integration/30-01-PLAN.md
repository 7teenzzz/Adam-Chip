### Task 1: Полностью удалить Ollama (REQ-NO-OLLAMA)

**Files:** (runtime/host — без правок кода в репо)

**read_first:** `30-CONTEXT.md` (D-04), `~/.claude/.../memory/feedback_no_ollama.md` (инвариант)

1. Остановить и отключить: `sudo systemctl stop ollama && sudo systemctl disable ollama`.
2. Удалить unit: `sudo rm -f /etc/systemd/system/ollama.service && sudo systemctl daemon-reload`.
3. Удалить бинарь: `sudo rm -f /usr/local/bin/ollama` (ставился install-скриптом, не apt — проверить `which ollama`; если apt — `sudo apt-get purge -y ollama`).
4. Удалить модели/данные: `rm -rf ~/.ollama` (gemma3:4b ~3.3 GB — пользователь согласовал purge).
5. Удалить служебного юзера, если создан: `id ollama` → при наличии `sudo userdel ollama` (не трогать, если используется чем-то ещё).

**Verify:**
```bash
which ollama || echo "ollama removed from PATH"
ss -tlnp | grep 11434 || echo "11434 not listening"
ls /etc/systemd/system/ollama.service 2>/dev/null && echo "UNIT STILL PRESENT (fail)" || echo "unit gone"
free -h | awk 'NR<=2'   # свободная память выросла
```

### Task 4: Поднять стек канонической tooling'ой adam_start.sh (REQ-SERVICES-STABLE)

**Files:** (systemd/docker/bare runtime через скрипты)

**read_first:** `scripts/adam_start.sh`, `scripts/adam_stop.sh`, `scripts/adam_service_restart.sh`, `CLAUDE.md` (Gemma --reasoning off)

**ФАКТ (проверено в этой сессии):** start/stop/restart любого `adam-*.service` работают БЕЗ пароля (sudoers NOPASSWD wildcard, по ОДНОМУ сервису на команду). 1. Предусловия: Ollama снесена (Task 1 → VRAM свободна, иначе llama.cpp OOM), сеть ESP поднята (Task 2), конфликт 8095 устранён (Task 3, иначе Docker ASR не сможет bind).
2. Поднять весь стек одной командой: `./scripts/adam_start.sh` (idempotent; llm systemd, tts systemd, asr Docker, оркестратор bare с env, VLM если есть). Управление по ходу: `./scripts/adam_service_restart.sh --llm|--tts|--asr|--orchestrator`, стоп: `./scripts/adam_stop.sh`.
3. Проверить gate: llm.ok, tts.ok, asr.ok, mcu (ESP, после Task 2).

**Verify:**
